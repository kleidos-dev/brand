# AGENTS.md — brand

This is the brand repository of Kleidos, the open-source hardware password manager: the mark and its lockups, the design tokens, the pinned fonts, the palette, the press kit, the public facts and texts about the project, and the Kleidos KiCad style. Nearly every picture and generated file here is written by one Python builder from a few hand-kept sources, and checked by it. For now the firmware repository is the source of the device's palette, the site's tokens, the mark, the font pins and the site's words, and this repository mirrors them; the social pack under `social/` (the profile images, repository cards and README banners, which was the `kleidos-dev/social` repository until 2026-11-24) is drawn by its builder package, and `boards` and the meter take its KiCad kit. It is public at <https://github.com/kleidos-dev/brand>. The artwork is GPL-3.0-or-later and the tokens, tooling and texts MIT, file by file in `REUSE.toml`. Everything here is published under the owner's name, so the rules below about the mark, colors, words and facts are the product's identity, not style preferences. [README.md](README.md) says how it is built for a human reader.

## What is where

- `logo/src/mark.svg`: the mark, the only drawing kept by hand. `logo/src/lockups.json`: the lockups' numbers. `logo/src/small-mark.json`: the small mark's sizes and pixel rules (owner, 2026-11-18: under 24 px, the ring and a solid body in the ring's color with the keyhole cut out; from 24 px, the full mark). `logo/src/opaque.json`: the ground each opaque copy of a logo PNG on transparency is flattened on (white for a light-ground variant, black for a dark-ground one and for the mark in color). `logo/svg/`, `logo/png/` (opaque copies included), `logo/webp/`: generated. `logo/README.md`: the logo's rules of use.
- `fonts/`: the upstream font files, unmodified, with `fonts/VERSIONS.md` (pins) and each family's `OFL.txt`.
- `tokens/tokens.json`: the one file of values. `tokens/dist/`: generated. `tokens/mirror.json`: written by `tools/sync_from_kleidos.py --record`.
- `colors/`: the palette's page and sheet, generated from the tokens.
- WebP: every published PNG and JPEG file has a WebP copy of the same name, written by the builder (`tools/kleidos_brand/webp.py`): beside it, or under `logo/webp/` for a logo PNG; lossless from a PNG's pixels, quality 90 for a photograph; the encoder's version is recorded in `exports.json`.
- `about/`: `about/facts.json` and the texts held to it.
- `kicad/`: the Kleidos KiCad style (`kicad/README.md` holds its rules). `kicad/src/style.json` by hand; the two drawing sheets (`kleidos-<ground>.kicad_wks`, the mark embedded as the logo PNG's bytes), the two color themes (`kleidos-<ground>.json`, from the `schematic` tokens) and the resolved `kicad/style.json`: generated by `tools/kleidos_brand/kicad.py`. `kicad/kleidos_kicad.py` (how kicad-cli is run with the kit) and `kicad/fixture/` by hand. `kicad/preview/`: generated with `tools/build.py --kicad`, which needs the KiCad release CI runs (the `kicad/kicad` image in `.github/workflows/check.yml`).
- `boards/`: byte copies of the board fronts of the `boards` repository (`<board>/svg/front.svg` there, MIT) and `boards/boards.json`, each copy's digest and the commit it was taken at, written by `tools/sync_from_boards.py --copy`. `tools/kleidos_brand/boards.py` draws them into an image at one scale.
- `press-kit/src/`: one SVG template per layout and `press-kit/src/press.json` (the words, the images made from each layout, the screens). `press-kit/svg/`, `press-kit/images/` and the enlarged files of `press-kit/screens/`: generated. The native captures in `press-kit/screens/` hold the firmware repository's pixels, pixel for pixel, with their own metadata written by the builder. `press-kit/photos/`: the owner's photographs, each full-resolution file written once by `kleidos_brand.photos.clean` from the camera's file (listed in `press.json`, with credit and alt texts), and its narrower copies, generated.
- `tools/kleidos_brand/`: the builders and checks as one package, which the social pack (`social/tools/`) imports too; keep what both need there. `tools/build.py`, `tools/check.py`, `tools/check_metadata.py`, `tools/check_kicad.py`, `tools/sync_from_kleidos.py`, `tools/sync_from_boards.py`, `tools/sync_kicad.py`: the commands. `tests/`: their tests.
- `exports.json`: the record of what each picture was drawn from, written by the builder.
- `social/`: the social pack, a project of its own inside this tree, with its own rules (`social/AGENTS.md`), data (`social/pack.json`), sources, generated pictures, exporter, check and tests; `social/MOVED.md` says how it came from the `kleidos-dev/social` repository. `tools/check.py` leaves `social/` to `social/tools/check.py` (`OWN_CHECKS`) but for the licensing of `REUSE.toml` and `LICENSES/`, and `pyproject.toml` gives mypy a group for it.
- The README banner: the block at the top of `README.md` reads both files from this repository's `main` by their raw address (`kleidos-dev/brand/main/social/svg/readme/brand/banner-{dark,light}.svg`), as every kleidos-dev README does; the block is printed and checked by `social/tools/sync_readme_banners.py` (`--print brand`, `--check . --repo brand`).
- The Kleidos quality kit (`kleidos-dev/.github/docs/quality.md`) runs here by its name, `@v3`, and none of its code is held here. `.github/workflows/check.yml` calls its entry workflows (quick, check and sonar) beside this repository's own jobs, and its last job, `✅ Check`, is the one required check; `.github/workflows/commit-check-comment.yml` calls its commit-check comment; `.pre-commit-config.yaml` takes its hooks (`kleidos-kit`, `kleidos-commit-msg`, `kleidos-mypy`) at a release tag, beside the third-party hooks it holds to its canonical list. What stays in the tree: its base configurations (`.github/quality/ruff.toml`, `.github/quality/markdownlint.jsonc`, `.gitleaks-mac.toml`, `.github/zizmor.yml`), never edited here and recorded with their digests in `.github/quality/SOURCE.json`, and `.github/quality/waivers.toml` (this repository's own weakenings of a kit rule, each with its reason).
- Review bots: CodeRabbit (`.coderabbit.yaml`) and Greptile (`.greptile/`), inline comments and suggestions only. Their path rules restate this file's rules and their ignore lists name the generated and copied paths above, so a change to either here changes them in the same change.

## Commands

Set up once per clone, with the Python of `.python-version`, and a checkout of the quality kit at the release tag `.pre-commit-config.yaml` gives its hooks (`rev`) beside this one as `../.github`:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install --require-hashes -r ../.github/quality/requirements-tools.txt
.venv/bin/python -m playwright install chromium
. .venv/bin/activate                                   # the hooks find mypy and the rest on the PATH
pre-commit install --hook-type pre-commit --hook-type commit-msg
```

Before a commit, with the virtual environment active:

```sh
pre-commit run --all-files                             # the quality kit's hooks, tools/check.py and social/tools/check.py
python tools/check.py                                  # the tree's rules
python social/tools/check.py                           # the social pack's rules, its pictures against their record (social/AGENTS.md has the pack's other commands)
python tools/build.py --check --static                 # every generated file, what needs no browser
python tools/build.py --check                          # pixel for pixel; refused under a browser other than the one exports.json records
python tools/build.py --check --tolerant               # what CI runs instead: draw again, fail on gross drift
python -m pytest tests
python -m pytest social/tests                          # the pack's tests, in a pytest of their own (both trees have a check module)
reuse lint
python tools/sync_from_kleidos.py --check <checkout of the firmware repository>   # when tokens, the mark, the fonts or copied words changed
python tools/sync_from_boards.py --check <checkout of the boards repository>      # when a front changed there
python tools/build.py --kicad --check --static         # after a change to kicad/, with kicad-cli; python tools/check_kicad.py exports the fixture as CI does
```

`python tools/build.py` regenerates everything the builder owns; `python tools/build.py --zip` writes the press-kit archive under `dist/`, which is not committed. The kit's minor and patch releases reach CI by themselves through `@v3`, and Dependabot moves the hooks' tag; a new major is a pull request by hand that moves both and carries the fixes it asks for (`kleidos-dev/.github/docs/quality.md`, "Versions"). From the kit's checkout, `python ../.github/quality/policy.py --repo .` runs the check of the lint job, and `python ../.github/tools/kit_switch.py --configs .` takes its newer base configurations.

CI (`.github/workflows/check.yml`, workflow `CI`) runs, cheapest first: the kit's quick call (its policy and every hook but `brand-check` and `social-check`, licensing with `reuse lint` and the header lines over the whole history, the gitleaks scan of the whole history, and on a pull request the commit messages) and the tree's job (`tools/check.py`, `tools/build.py --check --static` and `social/tools/check.py`, the only job that reads the private deny-list); once both pass, the kit's check call (brand's tests, then the social pack's in a second pytest, with `tools/build.py --check --tolerant` and `social/tools/export.py --check --tolerant`, mypy in its two groups, the OSV gate on the pinned dependencies) and the KiCad kit's export; and last the kit's secretless SonarCloud analysis (`sonar-project.properties`, coverage through `.coveragerc`; only what a properties file cannot carry is set in the SonarCloud UI). The last job, `✅ Check`, needs every other one and is the one required check. A weekly run repeats everything but the KiCad export and SonarCloud, for OSV.

## Rules of this repository

- **Generated files are never edited by hand.** Change the source and run `tools/build.py`, commit the regenerated files with the change that caused them, and **look at every image you produced** before committing it, small sizes and both grounds included. `tools/build.py --check` and CI fail on a stale file.
- **The mark is always whole.** The keyhole inside its ring, at any size, in every file. No ringless glyph, no redrawn or recolored copy: a file shows the mark as a `<g class="mark">` holding the five shapes of `logo/src/mark.svg`, as the one-ink mark the builder derives from them, or, under 24 px, as the small mark (`<g class="mark mark-small">`) the builder fits from them to one of the sizes of `logo/src/small-mark.json`. `tools/check.py` refuses anything else.
- **True colors, tokens only.** Every color in a source or an image is a token's value. No opacity, tint, gradient, shadow or filter. A new color is a new token first. Two things keep their own colors, because they are pictures of something real: a screen capture keeps its pixels, and a board front (`boards/`) keeps its case's true colors, gradients included, as the boards repository draws it; only its drop shadow is left out.
- **No live text in anything published.** Words are outlines, made by `tools/kleidos_brand/lettering.py` from the pinned fonts. The name is the one lettering path and is never retyped.
- **Fonts stay unmodified.** Only the pinned upstream files are in the tree. Never save a subset, an instance or a converted copy: it would be a Modified Version under the OFL, and Mona Sans reserves its name.
- **Licenses.** The artwork authored here (the mark, the lockups, the press images and their templates and words, the screen captures, the palette's sheet) is GPL-3.0-or-later, the firmware's license. The tokens and their generated files, the tooling (`tools/`, `tests/`, the CI, the pins), the texts under `about/`, the two fact sheets and the board fronts copied from `boards` are MIT (owner, 2026-11-17). `REUSE.toml` draws the line file by file; a new file takes the license of what it is. Third-party material keeps its own license, which must be approved by the OSI; no Creative Commons license, no custom terms, no "all rights reserved". In Markdown the two SPDX lines are an HTML comment at the top (`python3 ../.github/quality/spdx_headers.py --repo . --write` from the kit's checkout adds them), and a text quoted as it is (`about/`) is read without it (`kleidos_brand.public_tree.prose`). A file that cannot carry a comment (a picture, JSON, an SVG whose header the builder writes, a KiCad sheet) is stated in `REUSE.toml`, never by a `.license` file. A new kind of file is covered by `REUSE.toml` in the same change, and a new third-party source gets its notice in `NOTICE.md`. The GPL here carries two additional terms, 7(e) (no trademark rights) and 7(c) (a modified version is marked as changed and does not misrepresent its origin), and one additional permission, the press permission. The name and the mark: `TRADEMARKS.md`, whose wording changes only with the owner's yes.
- **Boards come from `boards`, as copies.** The fronts under `boards/` are byte copies held to `boards/boards.json`; a new or changed front is copied with `tools/sync_from_boards.py --copy`, never drawn or edited here, and the images are built again and looked at. A board drawing anywhere else in the tree is refused (`tools/check.py`). The fronts keep what is printed on the products, the makers' marks included, as the boards repository draws them; those marks are their owners' (`NOTICE.md`).
- **No capture that shows another company's mark**, and no vendor file of any kind. A photograph is the owner's own, given for publication, and shows the boards as they are, their makers' print included; it goes in only through `kleidos_brand.photos.clean`, with no camera data: no EXIF, color profile or comment, only the profile's XMP and IPTC the builder writes (`tools/check.py` reads every segment), and its README says when its screens show an earlier build.
- **Every published file says what it is.** Each picture and SVG the builder writes carries the record `tools/kleidos_brand/records.py` makes for it, in the slots and order of the metadata profile (`tools/kleidos_brand/meta.py`, `kleidos-media-meta/1`): title, description, alt text, author, copyright line, license (SPDX identifier and URL, as `REUSE.toml` says for the path), keywords, the file's public URL, and how it was made. Never by hand and never with exiftool: change a record and build again. No date, tool name, path, host or e-mail address goes in, and no camera data (`tools/check.py`, rule `metadata`; also `tools/check_metadata.py`). The private deny-list those checks read lives in the untracked `tools/deny-local.txt` or the `KLEIDOS_DENY_EXTRA` secret, never in the tree; without it `tools/check.py` warns that identity patterns were not checked.
- **E-mail addresses.** The only one in the tree is mail@kleidos.dev (the contact): the supplier `REUSE.toml` names is a name only, and no copyright line carries an address (`tools/check.py`, rule of the public tree; the kit's licensing rule).
- **Facts are public facts.** `about/facts.json` holds only what a public page of the project already states, or what the owner has given for publication (the value's `source` then says so), with `as_of` on what ages. The texts say nothing about unpublished work. Never print the registered-trademark sign beside the name.
- **Words.** Spanish never says "vault" or "bóveda": the container is "llavero", its content "tus contraseñas". The mark's inner glyph is a keyhole: "keyhole" in English and «cerradura» in Spanish, never "key" or «llave»; the texts use those words for the Greek word behind the name, an encryption key and the FIDO2 security key Kleidos is not, never for the glyph. The vendors are written "M5Stack" and "LILYGO" (owner, 2026-11-18), as `about/facts.json` lists them; the board fronts under `boards/` keep the boards repository's print until it changes there. Files are in US English but the Spanish texts.
- **Not only the StickS3.** Where boards or their screens appear, the other boards appear too.
- **Pull requests only.** `main` only moves forward, by pull request.
