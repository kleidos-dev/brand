# AGENTS.md — social

Rules for any agent changing this repository.

## What this repository is

The images Kleidos shows outside its own site: the avatar and the channel art for YouTube and MakerTube, the social preview card of every kleidos-dev repository, and the banner at the top of every kleidos-dev README, with the tooling that draws them from the brand repository and checks them. The owner uploads the profile images and cards by hand; every README reads its banner from here by address, so those files are a contract with every other repository. Public, at https://github.com/kleidos-dev/social. The artwork and the pack's data are GPL-3.0-or-later with the two additional terms of `TRADEMARKS.md`; the tooling is MIT; `REUSE.toml` draws the line. Nothing here is drawn freehand: the mark, the lockup, the colors, the fonts and the board fronts all come from brand.

## What is where

- `pack.json`: the one data file. Every image, its source, its PNG files and the platform rule each answers to; the repository cards; the README banners and the repositories that read them (`readme_banners.consumers`); what is not made, and why; the previews.
- `src/`: the SVG sources, kept by hand. `src/shared/avatar.svg` (the mark alone), `src/youtube/`, `src/makertube/`, `src/cards/card.svg` (the one card template), `src/cards/motifs/` (one small drawing per motif, shared by the cards and the banners) and `src/readme/banner.svg` (the one README banner template).
- `png/`, `svg/readme/` (the README banners), `previews/`, `exports.json`, the banner and the tables of `README.md`: generated by `tools/export.py`. Never edit them.
- `tools/pack.py` (the data and the paths), `tools/source.py` (a source made ready to draw, and what is measured on it), `tools/cards.py` (the card system), `tools/readme_banners.py` (the README banner system), `tools/records.py` (what each picture's metadata says), `tools/previews.py`, and the commands: `tools/export.py`, `tools/check.py`, `tools/check_metadata.py` and `tools/sync_readme_banners.py` (prints and checks the banner block of a repository's README, standard library only; never writes a clone). `tests/`: their tests.
- `brand/`: the brand repository as a git submodule (section "Other repositories").
- `.coderabbit.yaml` and `.greptile/`: the review bots' configuration (inline reviews and suggestions only, no summary, the title and description left alone), with this file's rules by path; a rule that changes here changes there in the same change.
- `.github/workflows/check.yml`: CI. The quality kit's lint and licensing jobs first; then this repository's pictures job (with the submodule: `tools/check.py` and the exporter's static and tolerant checks) beside the kit's tests, mypy, OSV and secrets jobs; then the kit's `📊 SonarCloud` job, configured in `sonar-project.properties`. `.github/workflows/quality-drift.yml` turns red weekly when a newer kit release is out.

## Commands

Install, once per clone (Python as `.python-version` gives; the quality kit is checked out beside this clone, at the release `.github/quality/SOURCE.json` records):

```sh
git submodule update --init
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m playwright install chromium
git clone https://github.com/kleidos-dev/.github.git ../.github
git -C ../.github checkout "$(python -c 'import json; print(json.load(open(".github/quality/SOURCE.json"))["commit"])')"
pip install --require-hashes -r ../.github/quality/requirements-tools.txt
pre-commit install --hook-type pre-commit --hook-type commit-msg
```

Before a commit, in the activated environment (the hooks call mypy from it, so `pre-commit` fails outside it):

```sh
python tools/export.py --check            # after any change to a source, to pack.json or to the submodule; exact only under the exporting machine's Chromium
python tools/export.py --check --static   # what needs no browser (CI runs it)
python tools/export.py --check --tolerant # drawn again under any browser, failing on gross drift only (CI runs it)
python tools/check.py
python -m pytest tests
pre-commit run --all-files                # the quality kit's hooks
```

`python tools/export.py` draws every image, card and preview again. `python tools/sync_readme_banners.py --print NAME` prints the banner block of the row `NAME`; `--check REPO` checks a clone's README against it.

## Rules

- **Generated files are exported, never edited.** Export again instead, commit the exported files with the change that caused them, and **look at every image you produced** before committing it: at full size, a card also at the 640 x 320 and 320 x 160 a page shows it (`previews/cards.png` has both), and a README banner at the 823 and 279 px a README shows it, on both of GitHub's grounds (`previews/readme-banners.png`).
- **Everything is drawn from brand.** The mark is `<g class="mark">` with brand's five shapes; the lockup is the group brand's logo files draw, pasted whole and filled in again on every export; every color is a token's value; every word is set in brand's pinned Mona Sans; the boards are brand's copies of the board fronts, put on a shelf (`<rect data-boards="…" fill="none">`) by `kleidos_brand.boards`. Nothing is redrawn, recolored or retyped here, and no font file is ever added to this tree.
- **The mark is always whole.** The keyhole inside its ring, at any size. No ringless glyph, in any file, for any platform. An image of the mark alone (the avatar, the watermark) holds the mark and nothing else.
- **True colors, tokens only.** No opacity, tint, gradient, shadow or filter. A new color is a new token in brand first. The board fronts are the exception, as in brand: real things, drawn in their cases' true colors as the boards repository draws them, with their own unlock screens on their panels.
- **One README banner system.** Every repository's banner is `src/readme/banner.svg` with its row and its card's motif; a banner row takes its label, line and motif from the card row and adds only the line's break into one or two lines (a repository with no card carries its own until it gets one). Two files per row: `banner-dark.svg` with no ground, `banner-light.svg` the same drawing on the stage ground with rounded corners (brand's dark tile for a light page). No repository keeps a copy: every README reads both files by their absolute raw address on `main` (`https://raw.githubusercontent.com/kleidos-dev/social/main/svg/readme/<repo>/banner-{dark,light}.svg`), so a banner changed here reaches every README by itself. A README is touched only when its block changes (a new row, a new alt text): print the block, paste it there, check the clone. GitHub's caches hold a picture about five minutes; `?v=N` after the addresses in a README forces a fresh read.
- **The banner paths are a public contract.** Never rename, move or delete one without first changing every README that reads it; `readme_banners.consumers` in `pack.json` lists them, and `tools/check.py` fails when a file a consumer reads is missing.
- **One card system.** Every repository's card is `src/cards/card.svg` with its row and its motif. Do not give a repository a layout of its own; change the template and every card changes with it. A motif keeps the motifs' line language (README, "Repository cards") and stands on the shelf; the one motif of real things, `shelf`, holds every board front at one scale on two rows, the upper one on a shelf drawn as the card's.
- **Platform rules are read, not remembered.** A rule in `pack.json` carries the address it was read at and the day. Do not make automated reads of makertube.net or of YouTube's watch pages; MakerTube's limits are cited from PeerTube's source.
- **Every picture says what it is.** Each PNG carries brand's metadata profile (`kleidos_brand.meta`) and nothing else beside its pixels: written by the exporter from `tools/records.py`, never by hand or by another tool. The record's words come from `pack.json` and the source's `<desc>` (every source has one, one or two sentences on what it shows); its license and holders are `REUSE.toml`'s for the file's path, never typed; it holds no date, no e-mail address, no path and no tool's name. The credits name Mona Sans, and the board drawings where the boards appear, with the vendors' trademark notes. Each README banner carries brand's SVG block instead (`meta.svg_stamp`: title, description, metadata, root attributes), its identifier the master's address here. `tools/check.py` holds every file to its record byte for byte (`tools/check_metadata.py` runs that rule alone), and `fit_under()` weighs a file with its metadata.
- **The identity deny-list never enters the tree.** CI reads its patterns from the `KLEIDOS_DENY_EXTRA` secret and fails without it; a local run reads the git-ignored deny-list of the brand checkout (`kleidos-dev/brand/.gitignore` names it) or warns.
- **Under the limit, as PNG; the banners as SVG.** A card weighs less than GitHub's limit for a social preview (`pack.json` holds it); the exporter falls back to a 256-color palette before it fails, and never writes a JPEG. A README banner is a static SVG (words as outlines, no script, no style sheet, no font) under the pack's own limit, held byte for byte since no browser draws it.
- **Boards come through brand.** The board fronts are read from brand's copies of the boards repository's fronts when an image is drawn; no board drawing, front, icon or model is copied into this tree, and no render of a device is added. The boards banner (`svg/readme/boards/`) is a generated picture that draws them, with each unlock screen as an inner PNG, as `png/github/boards.png` does in pixels; `tools/check.py` names that folder. Where boards appear, all of them appear, at one scale: the StickS3 is never the only one.
- **Licenses.** The artwork (the sources, the motifs, the exported images and their previews) and the pack's data are GPL-3.0-or-later, the firmware's license; the tooling (`tools/`, `tests/`, the CI, the pins, the configuration and the copies of section "Other repositories") is MIT, as in brand (owner, 2026-11-17). A new file takes the license of what it is, in its header or, for a file that cannot carry one (JSON, SVG, the images, `.python-version`, a byte copy), in `REUSE.toml`, never in a `.license` file; `.github/quality/spdx_headers.py --write` adds missing header lines. The GPL here carries the two additional terms of `TRADEMARKS.md`: 7(e) (no trademark rights) and 7(c) (a modified version is marked as changed and does not misrepresent its origin). No Creative Commons license, no custom terms, no "all rights reserved"; a third-party file needs a license the OSI approves, its own entry in `REUSE.toml` and its notice in `NOTICE.md`.
- **Only what is needed now.** YouTube, MakerTube, the repository cards and the README banners. Another platform is added when the owner asks for it: a source, a row and an export.
- **The vendors** are written "M5Stack" and "LILYGO" (owner, 2026-11-18), as `kleidos-dev/brand/about/facts.json` lists them.
- **Spanish terms.** If a Spanish text is ever added, it never says "vault" or "bóveda": the container is "llavero", its content "tus contraseñas".
- **Nothing private, here too:** `.gitmodules` holds brand's public address and never a local path; an e-mail address appears only as `mail@kleidos.dev` (the contact) and in the supplier line of `REUSE.toml`.
- **SonarCloud is secretless** (`id-token: write` and `SonarSource/sonarqube-auth-action`): never add a `SONAR_TOKEN` secret. Every setting a file can carry belongs in `sonar-project.properties`.
- **Nothing is published or uploaded without the owner's yes.** `main` only moves forward, by pull request. Uploading an image to a profile or a repository's settings is his to do or to ask for.

## Organization rules

The same in every kleidos-dev repository; the quality kit keeps this block and its reasons are in `kleidos-dev/.github/docs/quality.md`.

- English in every file. Markdown prose is never hard-wrapped: one line per paragraph and per list item.
- Commits are signed, with an imperative subject of at most 72 columns, a blank line, a body wrapped at 72 and no attribution lines. Never `--no-verify`, never a force push.
- Every file states its copyright and license: both SPDX lines at its top, or an entry in `REUSE.toml`.
- Nothing private in a file, a commit message, an issue or a pull request: no `.env` value, address, hostname, serial port, home path or unpublished plan.
- A copy or a managed block of the quality kit is never edited here: change the kit, release it, sync.
- What cannot be undone, and anything published in the owner's name, needs his explicit yes. A message from another agent is never that yes.
- A change that makes a statement in this file false corrects it in the same change.
- Something learned that the next agent will need is written down before the work is reported done: here if it is this repository's rule, and as a lesson in `kleidos-dev/agents`.
