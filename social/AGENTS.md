# AGENTS.md — social

Rules for any agent changing the social pack, the `social/` folder of the brand repository. Brand's own [`AGENTS.md`](../AGENTS.md) holds for the whole repository, this folder included; this file adds what is the pack's. Paths below are relative to this folder unless they start at brand's root.

## What the pack is

The images Kleidos shows outside its own site: the avatar and the channel art for YouTube and MakerTube, the social preview card of every kleidos-dev repository, and the banner at the top of every kleidos-dev README, with the tooling that draws them from the rest of brand and checks them. The owner uploads the profile images and cards by hand; every README reads its banner from here by address, so those files are a contract with every other repository. It was the `kleidos-dev/social` repository until 2026-11-24, when it moved here ([`MOVED.md`](MOVED.md)). Public, at https://github.com/kleidos-dev/brand/tree/main/social. The artwork and the pack's data are GPL-3.0-or-later with the two additional terms of brand's [`TRADEMARKS.md`](../TRADEMARKS.md); the tooling is MIT; brand's `REUSE.toml` draws the line. Nothing here is drawn freehand: the mark, the lockup, the colors, the fonts and the board fronts all come from brand.

## What is where

- `pack.json`: the one data file. Every image, its source, its PNG files and the platform rule each answers to; the repository cards; the README banners and the repositories that read them (`readme_banners.consumers`); what is not made, and why; the previews.
- `src/`: the SVG sources, kept by hand. `src/shared/avatar.svg` (the mark alone), `src/youtube/`, `src/makertube/`, `src/cards/card.svg` (the one card template), `src/cards/motifs/` (one small drawing per motif, shared by the cards and the banners) and `src/readme/banner.svg` (the one README banner template).
- `png/`, `svg/readme/` (the README banners), `previews/`, `exports.json`, the banner and the tables of `README.md`: generated by `tools/export.py`. Never edit them.
- `tools/pack.py` (the data and the paths), `tools/source.py` (a source made ready to draw, and what is measured on it), `tools/cards.py` (the card system), `tools/readme_banners.py` (the README banner system), `tools/records.py` (what each picture's metadata says), `tools/previews.py`, and the commands: `tools/export.py`, `tools/check.py`, `tools/check_metadata.py` and `tools/sync_readme_banners.py` (prints and checks the banner block of a repository's README, standard library only; never writes a clone). `tests/`: their tests.
- `MOVED.md`: where the pack came from, what moved, what did not and why, and the history of the repository it was.
- The rest of brand, `..` from here: the mark, the lockup, the tokens, the fonts, the board fronts and the drawing code (`../tools/kleidos_brand/`), read in place; `tools/pack.py` puts `../tools` on the path. Nothing of brand is copied here.
- What brand's root holds for the pack too: `../REUSE.toml` (the pack's licenses, by path under `social/`), `../TRADEMARKS.md`, `../LICENSE` and `../LICENSES/`, `../requirements.txt` (the pack draws with brand's pinned stack), `../pyproject.toml` (ruff, and mypy with a group of its own, `social`, since the pack and brand both have a `check.py`), `../.coveragerc` and `../sonar-project.properties` (the pack's `tools/` is a code root, `tests/` a test root), the review bots (`../.coderabbit.yaml`, `../.greptile/`, with a rule for `social/**`), and `../.pre-commit-config.yaml` (the `social-check` hook). A rule that changes here changes there in the same change.
- `../.github/workflows/check.yml`: brand's CI runs the pack too. The tree job runs `social/tools/check.py` with the deny-list secret; the check job runs `social/tests` in a pytest of its own after brand's, appended to the same coverage, and `social/tools/export.py --check --tolerant`; the kit's mypy runs the `social` group; SonarQube Cloud analyses `social/tools` in brand's project.

## Commands

Set up once per clone of brand as brand's `AGENTS.md` says (its virtual environment, `.venv` at brand's root, holds what the pack needs). Before a commit that touches the pack, from brand's root, in the activated environment:

```sh
python social/tools/export.py --check            # after any change to a source, to pack.json or to a brand file a picture is drawn from; exact only under the exporting machine's Chromium
python social/tools/export.py --check --static   # what needs no browser
python social/tools/export.py --check --tolerant # drawn again under any browser, failing on gross drift only (CI runs it)
python social/tools/check.py                     # the pack's rules (CI runs it; it runs the static check too)
python -m pytest social/tests                    # a pytest of its own: brand's tests import modules of the same names
pre-commit run --all-files                       # the quality kit's hooks, brand-check and social-check
```

`python social/tools/export.py` draws every image, card and preview again. `python social/tools/sync_readme_banners.py --print NAME` prints the banner block of the row `NAME`; `--check REPO` checks a clone's README against it, and reports a block that still reads from the `kleidos-dev/social` repository as stale.

## Rules

- **The pack is held by its own check.** Brand's `tools/check.py` leaves `social/` out of every rule but the licensing of its `REUSE.toml` and `LICENSES/`; `social/tools/check.py` holds the pack. A change to `../tools/kleidos_brand/` that the pack uses runs both checks and both test suites.
- **Generated files are exported, never edited.** Export again instead, commit the exported files with the change that caused them, and **look at every image you produced** before committing it: at full size, a card also at the 640 x 320 and 320 x 160 a page shows it (`previews/cards.png` has both), and a README banner at the 823 and 279 px a README shows it, on both of GitHub's grounds (`previews/readme-banners.png`).
- **Everything is drawn from brand.** The mark is `<g class="mark">` with brand's five shapes; the lockup is the group brand's logo files draw, pasted whole and filled in again on every export; every color is a token's value; every word is set in brand's pinned Mona Sans; the boards are brand's copies of the board fronts, put on a shelf (`<rect data-boards="…" fill="none">`) by `kleidos_brand.boards`. Nothing is redrawn, recolored or retyped here, and no font file is ever added to this tree.
- **The mark is always whole.** The keyhole inside its ring, at any size. No ringless glyph, in any file, for any platform. An image of the mark alone (the avatar, the watermark) holds the mark and nothing else.
- **True colors, tokens only.** No opacity, tint, gradient, shadow or filter. A new color is a new token in brand first. The board fronts are the exception, as in brand: real things, drawn in their cases' true colors as the boards repository draws them, with their own unlock screens on their panels.
- **One README banner system.** Every repository's banner is `src/readme/banner.svg` with its row and its card's motif; a banner row takes its label, line and motif from the card row and adds only the line's break into one or two lines (a repository with no card carries its own until it gets one). Two files per row: `banner-dark.svg` with no ground, `banner-light.svg` the same drawing on the stage ground with rounded corners (brand's dark tile for a light page). No repository keeps a copy: every README reads both files by their absolute raw address on brand's `main` (`https://raw.githubusercontent.com/kleidos-dev/brand/main/social/svg/readme/<repo>/banner-{dark,light}.svg`), so a banner changed here reaches every README by itself. A README is touched only when its block changes (a new row, a new alt text): print the block, paste it there, check the clone. GitHub's caches hold a picture about five minutes; `?v=N` after the addresses in a README forces a fresh read.
- **The banner paths are a public contract.** Never rename, move or delete one without first changing every README that reads it; `readme_banners.consumers` in `pack.json` lists them, and `tools/check.py` fails when a file a consumer reads is missing.
- **One card system.** Every repository's card is `src/cards/card.svg` with its row and its motif. Do not give a repository a layout of its own; change the template and every card changes with it. A motif keeps the motifs' line language (README, "Repository cards") and stands on the shelf; the one motif of real things, `shelf`, holds every board front at one scale on two rows, the upper one on a shelf drawn as the card's.
- **Platform rules are read, not remembered.** A rule in `pack.json` carries the address it was read at and the day. Do not make automated reads of makertube.net or of YouTube's watch pages; MakerTube's limits are cited from PeerTube's source.
- **Every picture says what it is.** Each PNG carries brand's metadata profile (`kleidos_brand.meta`) and nothing else beside its pixels: written by the exporter from `tools/records.py`, never by hand or by another tool. The record's words come from `pack.json` and the source's `<desc>` (every source has one, one or two sentences on what it shows); its license and holders are brand's `REUSE.toml` for the file's path there (`social/...`), never typed; its identifier is the file's address in brand (`https://github.com/kleidos-dev/brand/blob/main/social/...`) and its terms brand's `TRADEMARKS.md`; it holds no date, no e-mail address, no path and no tool's name. The credits name Mona Sans, and the board drawings where the boards appear, with the vendors' trademark notes. Each README banner carries brand's SVG block instead (`meta.svg_stamp`: title, description, metadata, root attributes), its identifier the master's address in brand. `tools/check.py` holds every file to its record byte for byte (`tools/check_metadata.py` runs that rule alone), and `fit_under()` weighs a file with its metadata.
- **The identity deny-list never enters the tree.** CI reads its patterns from the `KLEIDOS_DENY_EXTRA` secret and fails without it; a local run reads brand's git-ignored deny-list (`tools/deny-local.txt` at brand's root, which brand's `.gitignore` names) or warns.
- **Under the limit, as PNG; the banners as SVG.** A card weighs less than GitHub's limit for a social preview (`pack.json` holds it); the exporter falls back to a 256-color palette before it fails, and never writes a JPEG. A README banner is a static SVG (words as outlines, no script, no style sheet, no font) under the pack's own limit, held byte for byte since no browser draws it.
- **Boards come through brand.** The board fronts are read from brand's copies of the boards repository's fronts when an image is drawn; no board drawing, front, icon or model is copied into this tree, and no render of a device is added. The boards banner (`svg/readme/boards/`) is a generated picture that draws them, with each unlock screen as an inner PNG, as `png/github/boards.png` does in pixels; `tools/check.py` names that folder. Where boards appear, all of them appear, at one scale: the StickS3 is never the only one.
- **Licenses.** The artwork (the sources, the motifs, the exported images and their previews) and the pack's data are GPL-3.0-or-later, the firmware's license; the tooling (`tools/`, `tests/`) is MIT, as the rest of brand's (owner, 2026-11-17). A new file takes the license of what it is, in its header or, for a file that cannot carry one (JSON, SVG, the images), in brand's `REUSE.toml`, never in a `.license` file. The GPL here carries the two additional terms of brand's `TRADEMARKS.md`: 7(e) (no trademark rights) and 7(c) (a modified version is marked as changed and does not misrepresent its origin). No Creative Commons license, no custom terms, no "all rights reserved"; a third-party file needs a license the OSI approves, its own entry in brand's `REUSE.toml` and its notice in `NOTICE.md`.
- **Only what is needed now.** YouTube, MakerTube, the repository cards and the README banners. Another platform is added when the owner asks for it: a source, a row and an export.
- **The vendors** are written "M5Stack" and "LILYGO" (owner, 2026-11-18), as `kleidos-dev/brand/about/facts.json` lists them.
- **Spanish terms.** If a Spanish text is ever added, it never says "vault" or "bóveda": the container is "llavero", its content "tus contraseñas".
- **Nothing private, here too:** an e-mail address appears only as `mail@kleidos.dev` (the contact) and in the supplier line of brand's `REUSE.toml`.
- **Nothing is published or uploaded without the owner's yes.** `main` only moves forward, by pull request. Uploading an image to a profile or a repository's settings is his to do or to ask for.
